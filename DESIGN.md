# Editing workspace

Audience: Nimo (content approver), country editors, Derrick (hosting administrator).
Goal: change real website content without code while preserving its existing layout.
Constraint: local development only; the production domain has changed to WordPress and requires owner reconciliation before deployment.

Navigation: Overview / Website pages / Media library / Revision history / Team / Help.
Primary path: select page → click text/image in preview → edit plain fields → save draft → inspect preview → administrator publishes.
Recovery: history → load earlier revision as draft → inspect → publish. Never silently delete the current version.
Media: select file → confirm publication rights → upload → choose from library in an image field.

Layout: dark navy sidebar; cream workspace; orange primary actions; card grid for pages. Editor has a field panel next to a resizable website preview; tabs on narrow screens.
Tokens: navy #13233f; paper #f7f5f0; ink #18253b; muted #596575; orange #a43d1b; green #176a4d. System sans text; serif overview headline. 4/8/12/16/24/32/48 spacing. Visible focus rings and accessible native form controls.
States: loading, unsaved changes, server-saved draft, published, conflict, forbidden, offline/save failure. A failed save keeps local edits. Leaving a dirty page requires confirmation. Publishing and restoring require review dialogs. Counter target and display label remain separate explicit fields; no automatic unique-person totals.

Initial scope: edit existing wording, links, images, video links, captions, contacts and numerical fields on all imported pages. New arbitrary sections/page layout authoring, volunteer intake automation, automatic deduplicated impact totals, Google Drive writes and newsletter delivery are not included.
